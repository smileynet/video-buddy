# Qualify broader subject tracking only when a concrete task requires it

## Intent source and context

Reconciliation of tickets 25/36 on 2026-10-25 after the user requested Compass routing and said proceed. Read `docs/architecture/spikes/revision-boundary-results.md` and the three subject-frame-seeking reports. Existing bounded results reject the packet/event selector as a default; no new selector is integrated.

## What to build

Only activate when a named apply/build task fails with the retained baseline and the missing evidence requires broader subject tracking. Select ONE deciding question before implementation: repeated-command occurrence identity/history loss, moving text extent outside a seeded viewport, mask-versus-box completeness, diagram association, or source-wide discovery. Do not rerun every model or combine these into an unbounded benchmark.

Freeze a small development set and new independently checked validation windows, task-required commands/checkpoints, budgets and stop rule before inference. Compare against the simple time grid across offsets and budgets; report exact text separately from visual state coverage. Reuse existing evidence and record stage costs and actual correction effort where observed.

## Acceptance criteria

- [ ] Record the concrete failed task, missing evidence and why existing results cannot decide it.
- [ ] Freeze one question, baseline, independent references, validation split and active timebox before comparison.
- [ ] Report state/occurrence and text errors, unsupported associations, costs and reproducible evidence for all eligible options.
- [ ] Give an adopt/reject/unresolved verdict with residual limits; no production integration or invented user measurements.

## Deferral and reactivation

Deliberately deferred research, not a blocker for retaining the baseline or for review 28. Reactivate only on a documented task failure or an explicit decision to integrate the affected capability. Ticket 26 owns modality/action-order evidence; 21 owns fresh-performer outcomes; 30/33/34 own provider access/runtime gaps. This ticket does not absorb those obligations.

## Out of scope

Production changes, universal model ranking, further tuning on the locked validation windows, or claiming mask/tracking benefits from setup success.
