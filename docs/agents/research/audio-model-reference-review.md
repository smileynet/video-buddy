# Audio model reference reviewer

Checked 2026-10-25. Scope: three clips of about 55 seconds; Windows x64, Python 3.13, existing ONNXRuntime, no Torch/Transformers. Research only: no installation or inference performed.

## Recommendation (inference from verified findings)

Use **sherpa-onnx 1.13.6 CPU with SenseVoiceSmall int8, 2024-07-17 export** as the verified runnable next experiment. Install into an isolated disposable environment rather than change the project lock. Download the official archive, use its `model.int8.onnx` and `tokens.txt`, and adapt the official file-decoding example. Feed the actual audio, independently of Whisper text. Split inputs longer than 30 seconds into bounded overlapping windows of at most 30 seconds, retaining window offsets and raw results; review disagreements against the audio. Store these as **model-reviewed references**, separately from human-reviewed ground truth. Agreement between recognizers is evidence, not proof.

This is a distinct non-autoregressive model family, not another Whisper checkpoint. CPU avoids unverified Windows GPU dependency combinations. It is an audio recognizer, not an instruction-following audio judge: it generates a second transcription for comparison and cannot certify which transcript is correct.

For a blind comparison, pass audio and neutral clip identifiers only: no candidate transcripts, publisher captions, video titles or hints about expected words. Freeze the model-reviewed reference files, raw outputs and provenance before running or inspecting the Whisper candidates. This controls reference contamination; it does not turn an automatic reference into human ground truth. Local reference evaluation appears consistent with the model agreement's reference/learning scope (interpretation, not legal advice); no registration condition was found in the linked terms.

## Verified findings

- **High confidence — Windows/Python availability.** [PyPI 1.13.6](https://pypi.org/project/sherpa-onnx/1.13.6/) lists `sherpa_onnx-1.13.6-cp313-cp313-win_amd64.whl` (2.3 MB; uploaded August 18, 2026). Supporting snippet: “Tags | CPython 3.13 Windows x86-64”. This verifies an available binary, not execution on this machine. Newer 2.0.0 exists; 1.13.6 is a deliberate reproducible candidate, not a claim to latest.
- **High confidence — actual waveform input without Torch in the example.** [Official example, v1.13.6](https://raw.githubusercontent.com/k2-fsa/sherpa-onnx/v1.13.6/python-api-examples/offline-sense-voice-ctc-decode-files.py) imports sherpa_onnx and soundfile, reads float32 audio, selects channel zero, creates an OfflineRecognizer, and decodes its waveform. Snippets: “audio is a 1-D float32 numpy array”; “sample_rate does not need to be 16000 Hz”. Provide decoded mono WAV/float audio rather than assuming webm is accepted by soundfile. Mixing stereo deliberately may preserve speech better than blindly selecting channel zero.
- **High confidence — official compact model export.** [Maintainer release API](https://api.github.com/repos/k2-fsa/sherpa-onnx/releases/tags/asr-models), queried directly on the check date, returns the asset `sherpa-onnx-sense-voice-zh-en-ja-ko-yue-int8-2024-07-17.tar.bz2` with snippet `"size": 163002883` (about 155.5 MiB compressed). [Download](https://github.com/k2-fsa/sherpa-onnx/releases/download/asr-models/sherpa-onnx-sense-voice-zh-en-ja-ko-yue-int8-2024-07-17.tar.bz2). Disk size after extraction is not verified.
- **High confidence — token timing, not guaranteed word intervals.** [Official SenseVoice Python documentation, current](https://k2-fsa.github.io/sherpa/onnx/sense-voice/python-api.html) shows JSON with timestamp and token arrays and the snippet `"words": []`. It also demonstrates Silero-VAD subtitle generation. Preserve raw timestamps; do not label them human word boundaries or invent word-end times.
- **High confidence — independent architecture and language scope.** [Official checkpoint card, current](https://huggingface.co/FunAudioLLM/SenseVoiceSmall) describes a “non-autoregressive end-to-end framework”. The released checkpoint supports Mandarin, Cantonese, English, Japanese and Korean. Do not extend the broader research project's 50-language claim to this export.
- **High confidence — bounded direct inference.** [Current upstream README](https://raw.githubusercontent.com/FunAudioLLM/SenseVoice/main/README.md) says “input duration limit of 30 seconds or less.” This is the upstream direct-inference limit, not a verified hard limit in sherpa's export. Conservative overlapping windows avoid relying on unverified 55-second behavior; cuts can still change recognition. The current README and older HF examples differ in surrounding runtime APIs, so use sherpa's example with this ONNX export.
- **High confidence — package and model terms differ.** [sherpa license](https://raw.githubusercontent.com/k2-fsa/sherpa-onnx/master/LICENSE): “Apache License” / “Version 2.0, January 2004”. [Checkpoint metadata](https://huggingface.co/FunAudioLLM/SenseVoiceSmall/raw/main/README.md) instead says `license_name: model-license` and links FunASR's model agreement. Apache package licensing does not establish Apache checkpoint licensing.
- **High confidence — linked checkpoint agreement has custom restrictions.** [FunASR MODEL_LICENSE, current version 1.1](https://raw.githubusercontent.com/modelscope/FunASR/main/MODEL_LICENSE): “You are free to use, copy, modify, and share”; “must attribute the source and author information”. The full terms also require retaining model names, describe reference/learning use, include conduct-based termination and automatic revisions. Preserve the source/model attribution and snapshot the applicable terms with provenance; do not describe these weights as permissively Apache licensed.

## Could not verify / practical limits

- No local run was authorized for this research task: wheel dependency resolution, soundfile availability, model hashes, peak memory, latency, GPU providers, and transcription quality on the three clips remain unmeasured. The recommendation is runnable-by-documented-interface, not successful execution evidence.
- The ONNX archive's embedded license/provenance files were not inspected. Upstream checkpoint terms are linked above; record export provenance and inspect packaged notices before redistribution.
- Moonshine, Parakeet and Zipformer were not fully qualified here: no competing claim is made about their suitability. Stop shortlist expansion and try the verified candidate first unless its custom terms are unsuitable.
- No official evidence found here establishes this ASR as a reliable reference adjudicator. Keep recognizer outputs, comparison decisions and reviewer identity explicit; label unresolved spans rather than silently treating one model's text as truth.
