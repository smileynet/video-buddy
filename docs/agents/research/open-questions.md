## Verified findings that change the next experiments

### SAM 3.1 has a concrete source/API mismatch; access is no longer the blocker

**High confidence, source inspection plus prior runtime traceback.** The tested/current source revision is `f1647e8d0c1d280991f4d1b7d974c2704537fe66`. In [sam3_base_predictor.py](https://github.com/facebookresearch/sam3/blob/f1647e8d0c1d280991f4d1b7d974c2704537fe66/sam3/model/sam3_base_predictor.py#L140), `start_session` constructs `offload_state_to_cpu=offload_state_to_cpu`. The [multiplex model's init_state](https://github.com/facebookresearch/sam3/blob/f1647e8d0c1d280991f4d1b7d974c2704537fe66/sam3/model/sam3_multiplex_tracking.py#L2218) accepts `offload_video_to_cpu=False` but has no `offload_state_to_cpu` parameter or variadic keyword parameter. This explains the preserved `unexpected keyword argument 'offload_state_to_cpu'` failure. See [measured image-model results](../../architecture/spikes/image-model-results.md) for the traceback/evidence branch. A four-object multiplex bucket also mismatched checkpoint tensor shapes; retain bucket size 16.

**Disposition:** ticket 23 can test an experiment-only adapter that drops this argument only when false and explicitly rejects true. That would not implement CPU state offload. No adapter or tracking-quality result is claimed by this research. Bound the compatibility repair before spending time on abstract-diagram prompt tuning. Failed setup is not evidence of poor segmentation.

The [preserved authenticated metadata/HEAD recheck](checkpoint-access-2026-10-25.json) on 2026-10-25 now reports approved SAM 3, SAM 3.1 and **DINOv3**. DINOv3 revision `114c1379950215c8b35dfcd4e90a5c251dde0d32`, `model.safetensors`, 86,406,384 bytes. This supersedes the earlier 403, not the absence of DINOv3 inference evidence. Owner: ticket 23. No new credential action is required. Access approval does not itself settle model-use eligibility.

The [v3 asset LICENSE](https://huggingface.co/microsoft/OmniParser-v2.0/blob/f55d0750e5b94db2125ef0b45b0fa4a85ddc59b4/icon_detect_v3/LICENSE) says “MIT License”. ### A real local video-capable path is documented, but not yet benchmarked here

**High confidence in input contract; local temporal inference unresolved.** The [Qwen3-VL README, main read 2026-10-25](https://github.com/QwenLM/Qwen3-VL#new-qwen-vl-utils-usage) documents `return_video_metadata=True`, `image_patch_size=16` and `do_resize=False`. Its video examples allow sampling FPS/frame count and explicitly pass video metadata to the processor. It currently recommends torchcodec; its own page also contains an earlier decord recommendation. Pin one tested decoder/toolkit combination rather than copying incompatible examples. The tested local Qwen3-VL-2B run processed still images only.

**Disposition:** ticket 26 compares timestamped ordered images to a genuine local video input with recorded decoded frame indices/times, sampling and pixel/token budgets. Model-native video still involves decoding and sampling; it does not imply examining every source frame. A chat harness lacking video transport cannot evaluate that arm. Current external-agent video transport, privacy/retention and paid-provider budgets are unknown; no cloud provider is selected. Owner: 26, final policy 28.

### Downloader resume and archives are mechanisms, not pipeline completion

**High confidence in upstream mechanisms.** The [yt-dlp README, master read 2026-10-25](https://github.com/yt-dlp/yt-dlp#usage-and-options) says `--continue` will “Resume partially downloaded files/fragments”, and `--download-archive` will “Record the IDs of all downloaded videos”. It also documents browser-cookie import, retry limits and fragment retry behavior. This does not prove disk integrity, source access, guide completion or preservation of human edits. The source supports many sites; this application's downstream URL reconstruction is narrower.

**Disposition:** ticket 27 tests real acquisition seams plus deterministic local faults. Compare an archive entry with absent/corrupted media, partial download, configuration change, interrupted postprocessing and failed optional analysis. Verify streams/duration with ffprobe and exercise actual decode; neither metadata nor decoder success proves every instructional fact exists. Use explicit authentication-needed states, bounded retries and retained completed outputs. Do not import browser cookies automatically merely because the tool supports it. Tickets 09/10/11 remain implementation proposals gated by 28.
