# Ticket25, round2: controlled visibility and grid sensitivity

Throwaway branch `codex/spike-subject-frame-seeking`. No production integration.

The natural-video component reuses the first round's two frozen tutorial windows and OCR. The four new 6-second clips are **authored controls**, not naturally occurring tutorial footage. All480 decoded frames and their subject crops were checked against renderer geometry/occlusion labels. Three labels per clip: prepare, configure, verify. They are artificial stage text, not executable instructions.

## Run

Existing capture folders must be absent for build; do not remove unrelated data to reproduce. Build authors new fixture images/video, then calls the experimental repo capture CLI; it does not bypass source capture mechanics.

## Selection without label access

collect.py loads images, config and manually specified first-frame header coordinates. It does not load truth.json. The header template is searched over each whole image, with a0.8 confidence threshold. This is deliberately easy invariant-header association, not automatic semantic subject discovery. Full subject occlusion, scale/appearance change and multiple identical headers remain untested. Static and tracked OCR share an exact-box cache within a frame; do not sum both logical OCR totals as independent work.

evaluate.py first selects by observed OCR strings/quality; only measure() consumes frame labels. Frequency requires six total occurrences, ranking by count; events require two consecutive exact-string observations, ranking first occurrence with a sharpest representative. Both can spend budget on OCR variants/partial text. No oracle string filter, truth trajectory or manual removal of bad selections is used. A two-frame rule is also frame-rate dependent and is not a recommended production default.

## Labels and scoring

The viewport scrolls between three lines; complete glyph extents must be in the viewport. Motion translates the whole panel and adds blur around transitions. Occlusion covers part of the text from1.75–3.75seconds; stateB is clear only from3.75–4.00. The brief state is present from2.05–2.25seconds (four frames at20fps). These timings intentionally test temporal support and grid aliasing.

The recall unit is a **clean, complete visible state**: all glyphs present, no renderer obstruction, and predeclared severe-blur frames excluded. It is not a perceptual readability study. Text extent, not blank padding, must fit within a selected crop. Actual text bboxes are generated by the renderer; visual sheets and selected full-frame comparisons permit review. No independent human annotation or task-completion evaluation occurred.

Budgets1,2,3,4,6,8 are upper caps. Four offsets are0,.25,.5,.75 of one grid interval; times are `(i+offset)*duration/budget`. No wrapping, padding or source-wide discovery. A grid saves the whole frame, giving it no spatial tracking problem. It maps a request to the first decoded presentation time at/after it. capture_grid.py checked all192 distinct controlled seek requests through the core FFmpeg extractor: every result had zero mean absolute pixel difference from that decoded frame. Grid timing is the sum of cached per-request measured seek costs, not an independently repeated configuration benchmark. Natural-window grid variants use the presentation-time mapping without recapturing every variant.

## Artifacts

- `*.mp4`: complete controlled sources, tiny enough to retain; hashes in truth.json.
- `*-all-crops.jpg`: every decoded subject crop,120 per clip.
- `*-selection-comparison.jpg`: budget3/phase.5 full frames and crop extents for the grid and three PSM7 methods.
- `observations-psm*.json`: every OCR output, box, template confidence and stage duration.
- `results-psm*.json`: all96 grid configurations and72 subject-selector configurations per OCR pass, with selected-frame evidence, missed coverage, redundancy and incompleteness.
- `real-sweep.json`:48 natural-window grid configurations plus12 earlier seeker configurations.
- `memory-psm*.json`: nominal20ms sampled summed collector-plus-child RSS. Shared pages may be double-counted; short peaks may be missed. Decode/encoding and the monitor itself are excluded. No GPU memory claim.
- `grid-capture-audit.json`: actual seek verification and times.
- `dashboard-data.json`: compact exact values for the dashboard's budget drill-in.

versions.json records the installed runtime. The full collection plus two OCR passes is a small bounded diagnostic, not a repeated latency benchmark. Real scrolling/occlusion/motion on independently sourced tutorials, fresh validation after PSM7, peak decode memory, human correction effort and mask/model comparisons remain open.
